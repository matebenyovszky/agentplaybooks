# Supply-chain artifacts (SBOM, provenance, cosign)

This document is the operator-facing counterpart of the *Sérülékenységkezelés,
SDLC* and *Ellátási lánc* rows in the compliance table: CycloneDX SBOMs on
every `cli-v*` release, npm provenance for `@agentplaybooks/cli`, and keyless
cosign signatures over those artifacts.

It is not a completed supplier-questionnaire pack. *jogi ellenőrzés szükséges*

## What is produced

Workflow: [`.github/workflows/sbom.yml`](../../.github/workflows/sbom.yml).
Generator: [`scripts/generate-sbom.sh`](../../scripts/generate-sbom.sh).

| Artifact | When | Contents |
| --- | --- | --- |
| `sbom-npm.cdx.json` | Every SBOM job (PRs and tags) | CycloneDX 1.6 from the root `package-lock.json` |
| `sbom-cli.cdx.json` | Every SBOM job | CycloneDX 1.6 from `packages/cli/package-lock.json` |
| `sbom-python-secrets.cdx.json` | Every SBOM job | CycloneDX 1.6 for `packages/python-secrets` |
| `sbom-hermes-memory.cdx.json` | Every SBOM job | CycloneDX 1.6 for `packages/hermes-memory` |
| `sbom-image.cdx.json` | `cli-v*` tags only | CycloneDX 1.6 of the image built from the root `Dockerfile` |
| `SHA256SUMS` | `cli-v*` tags only | SHA-256 of the JSON SBOMs |
| `*.sigstore.json` | `cli-v*` tags only | cosign bundles (signature + Fulcio cert + Rekor proof) |

On PRs the JSON SBOMs are uploaded as a workflow artifact named `sbom`. They
are **not** signed. Signing needs GitHub OIDC (`id-token: write`) and is
intentionally limited to tags so a pull request cannot fail because Fulcio or
Rekor is unavailable.

On `cli-v*` tags the same files are attached to the GitHub Release for that
tag (the workflow creates the Release if one does not already exist). The npm
publish of `@agentplaybooks/cli` remains a **separate** workflow
(`publish-cli.yml`) and is not gated on SBOM or signing.

There is no container registry publish in this repository today. When one is
added, it must (a) run on tags, not PRs, (b) produce `sbom-image.cdx.json`,
and (c) `cosign sign` the image digest with the same GitHub OIDC identity.

## npm provenance (unchanged)

`publish-cli.yml` publishes with npm trusted publishing. Provenance
attestations are generated by npm from the GitHub OIDC token. Do not pass
`--provenance` and do not add an npm token.

Verify a published CLI package:

```bash
npm view @agentplaybooks/cli@<version> dist.attestations
npm audit signatures --package-lock-only   # from packages/cli after npm install
```

Or inspect the “Provenance” badge on the [npm package page](https://www.npmjs.com/package/@agentplaybooks/cli).

## Verify a signed SBOM

Install [cosign](https://docs.sigstore.dev/cosign/system_config/installation/).

Download from the GitHub Release for `cli-v<version>` (example: `sbom-npm.cdx.json`
and `sbom-npm.cdx.json.sigstore.json`), then:

```bash
cosign verify-blob sbom-npm.cdx.json \
  --bundle sbom-npm.cdx.json.sigstore.json \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp \
  '^https://github.com/matebenyovszky/agentplaybooks/\.github/workflows/sbom\.yml@refs/tags/cli-v.+$'
```

Repeat for `sbom-cli.cdx.json`, the Python SBOMs, `sbom-image.cdx.json`, and
`SHA256SUMS` (each has a matching `*.sigstore.json` bundle).

The certificate identity is the workflow file that signed the blob, at the
tag ref. Pull-request runs never match this regexp because they are not
signed.

After verifying `SHA256SUMS`, check the JSON files:

```bash
sha256sum -c SHA256SUMS
```

## Local generation (unsigned)

From the repository root, with Node 22+ and Python 3.10+:

```bash
./scripts/generate-sbom.sh
# writes dist/sbom/*.cdx.json
```

This path does not sign. Do not treat a locally generated file as a release
artifact.

## Comparing an SBOM to a running image

1. Verify the release `sbom-image.cdx.json` as above.
2. Rebuild the image from the same git tag (see `Dockerfile`) or, once a
   registry publish exists, pull by digest.
3. Generate a fresh CycloneDX document (`syft docker:<image> -o cyclonedx-json`)
   and diff component purls against the release SBOM.

A byte-identical match is not required (timestamps differ). Component names,
versions, and purls should match for production dependencies.

## SAST

CodeQL runs on pull requests, on `main`, and on a weekly schedule
([`.github/workflows/codeql.yml`](../../.github/workflows/codeql.yml)).
Findings appear on the repository Security tab. CodeQL does not replace
`npm run audit:production` or Dependabot; those stay in CI.

## Customer use (NIS2 Art. 21(2)(d))

Self-hosted customers can attach the verified SBOMs and the npm provenance
link to their supplier file. We do not file that assessment for them.
